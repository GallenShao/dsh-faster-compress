[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的长对话需要压缩上下文。原版在下一步开始前生成摘要，你要等它写完。**Faster Compress 把这件事提前到后台**：达到后台准备阈值后，任务利用安全余量继续推进；摘要就绪后，在下一次模型请求前应用。默认不发独立预热请求。

> **0.2.2**：回合正常结束后保留已准备的摘要，继续对话时直接校验复用，并修复后台任务与容量缓存的竞态。升级保留已有设置；推荐准备时机 **100%**、预热**关闭**。

## 安装，只填一个包名

打开 DSH 侧边栏的 **插件 → 添加插件**，输入：

```text
dsh-faster-compress
```

点击安装，完成后重新启动 DSH。**默认即用，无需 API Key，也不用编辑 YAML。**

已验证 **DSH 0.2.0-rc.2**，需要 **Node.js ≥ 22.19**。它沿用当前对话的模型和已有凭据；摘要、预热请求仍按模型服务的规则计费。

```sh
dsh plugin --profile web add dsh-faster-compress
```

## 装上后，改变了什么？

| 你遇到的情况 | Faster Compress 会做什么 |
| --- | --- |
| 达到后台准备阈值 | 后台开始准备摘要，主任务在安全预算内继续 |
| 摘要已经好了 | 在下一安全 step 边界应用，保留生成期间追加的消息 |
| 摘要未完成，达到安全等待线 | 暂停下一次主请求，等待摘要；没有可用准备时走原版压缩 |
| 应用后的正常请求 | 直接处理新上下文；不额外等待预热 |
| 摘要失败或旧内容被改写 | 丢弃准备结果，回退到原版同步压缩 |

它替换内置压缩后端，继续使用原版的摘要指令和提交事件格式。`/compact`、工具结果裁剪和图片卸载仍可使用。

## 每一次压缩，都有迹可循

打开会话顶部的 **压缩历史**：左侧按时间选择记录，右侧查看结果、执行时间线与内容。无需开启开发者模式。

- **结果一眼可辨：** 正在准备、待应用、安全线等待、已应用、已被后续替换，以及失败或丢弃的原因。是否应用以会话中的实际替换记录为准。
- **内容可以追溯：** 切换摘要、原始文本摘录与诊断信息，支持搜索、筛选和复制；保留模型、历史范围、token 估算及可获得的 usage 信息。
- **等待发生在哪里：** 分别展示后台生成、达到安全等待线后的等待、提交替换与预热耗时。生成与等待可能重叠，这些数字不代表节省的时间。
- **压缩后多久恢复输出：** 展示本轮因压缩阻塞到首输出、上下文替换到首输出，以及产生该输出的主请求 TTFT。另列首个思考、正文、工具增量相对应用时刻的时间；请求失败、重试和取消有独立记录。
- **排错无需翻日志：** 展示摘要失败、预热异常、过期丢弃、重载失效等信息。预热失败不影响可用摘要的提交。
- **检查前缀复用：** 展示摘要、预热和后续请求的缓存读取 tokens，以及请求的推理强度。服务未返回缓存计数时显示 `—`；预热完成、逻辑前缀匹配和实际缓存命中分别判断。

页面自动更新，支持中英文及 DSH 主题。每个会话展示最近 80 条记录；历史原生压缩也可读取，但缺失的后台耗时显示为 `—`，不会补造。

“已应用”以会话的上下文替换事件为准；“已进入主请求”则进一步核对 DSH 主请求中的检查点消息 ID 和压缩 ID。摘要生成和预热请求不会计入。这是在 DSH 调用边界的核验，不是模型服务的接收确认或缓存命中证明。

同一模型的摘要请求（包括手动、overflow 和原生回退）及预热会继承会话的 `reasoningEffort`，避免 provider 默认档位改变聊天模板前缀。指定不同摘要模型时保留该模型自己的默认值。预热会记录逻辑前缀指纹；路由、推理强度、system 或工具定义等变化会使旧预热失效，但不因此丢弃可用摘要，也不自动反复预热。新增尾部消息仍可复用此前前缀，新增部分需要正常 prefill。逻辑指纹不能观察服务端模板变化或缓存淘汰，实际收益仍需检查供应商统计。

响应计时使用服务端单调时钟，包含后续处理、模型排队及请求链路等待，不包含浏览器收到数据和绘制界面的时间。首输出按 DSH 口径取首个非空正文、思考或工具增量；分类时间忽略纯空白文本。跟踪应用后的首次主请求及其失败重试，正常结束后不再累计后续工具循环；若一次请求只有工具输出，正文时间显示 `—`。重试的 TTFT 按实际产生首输出的那次请求计算，总等待保留前面的失败和重试时间；每条记录最多保留最近 8 次尝试。手动 `/compact` 后的“应用后首输出”可能包含等用户输入的空闲时间，因此不计“本轮压缩阻塞”。重启或卸载会中断未完成的观测，旧记录不会据完成时间反推首 token。

主指标使用模型返回的 usage，展示替换前最近一次主请求与替换后首次回复对应的输入量（含缓存 token）。新增消息、工具结果及配置变化可能影响差额，因此不将其称为精确节省量。摘要请求的实际输入、输出和缓存命中单独显示；输出可能包含推理，不等于写回摘要的大小。旧片段与替换消息的字符估算仅作辅助信息。尚未返回 usage 时显示等待，缺失时显示未知，不以估算冒充实测；已有历史可从原生会话日志恢复这些计数。

诊断单独保存于 `$DSH_HOME/data/faster-compress/traces/`（默认 `~/.dsh/data/faster-compress/traces/`），不添加新的会话事件。每会话最多保留 80 条后台记录，原文摘录最多 12,000 字符，摘要最多 24,000 字符，截断时有提示；这里只保留文本，不存附件。常见凭据格式会从错误信息中遮蔽，原文和摘要则按会话内容保存。文件不可写时继续压缩，并在 压缩历史页提示。

关闭设置中的 压缩历史标签只隐藏入口，不停止诊断记录。需要清除这些本地副本时，先停止 DSH，再删除上述目录；DSH 原生会话日志中的已提交摘要仍由 DSH 管理。

**历史页提示 `strict definition was withdrawn`？** 这是旧开发构建的历史服务注册缺陷，当前分支已修复；安装更新后在任务结束时重启 DSH，再刷新页面。历史文件无需删除，也不要关闭严格 RPC 校验。

**插件更新后预生成结果丢了怎么办？** 后台准备只存在内存中，重启后不会从诊断文件重新应用旧摘要。没有可用结果时，会在安全预算内重新后台准备；已到安全等待线则直接回退原版同步压缩。摘要失败或选区过期时，按准备阈值判断并回退；重载打断等待且当前回合未取消时也会回退。用户主动取消回合则保持取消。插件只在会话 preset 内接管原生后端，接入失败会撤销替换并保留原生后端；禁用或卸载时恢复原生后端。热加载不改已有会话使用的后端，安装后请在任务结束时重启 DSH。

## 在设置页调整，不用找配置文件

进入侧边栏 **插件 → 已安装 → 更快压缩 · Faster Compress**，设置直接显示在插件详情页中。修改后点“保存”，后续准备与预热即采用新值，无需重启。

| 设置 | 默认值 | 什么时候需要调？ |
| --- | --- | --- |
| 后台准备时机 | **100%** | 使用后台准备阈值；经常触及安全等待线时可调低 |
| 预热新上下文 | **关闭** | 工具耗时较长、模型服务有余力且能复用缓存时可尝试开启 |
| 显示压缩历史标签 | **开启** | 保存后立即显示或隐藏会话中的 压缩历史页；保留诊断记录 |
| 更多选项 → 输出预留下限 | **0（自动）** | 请求/适配器未声明时填真实输出上限，例如 Qwen 的 32768；否则暂用原生压缩 |
| 更多选项 → 输入安全余量 | **4096 tokens** | 输入上限前保留的估算余量 |
| 更多选项 → 后台摘要并发数 | **1** | 多会话同时运行，且模型服务确实有余力时调高 |
| 更多选项 → 预热输出上限 | **1 token** | 通常无需修改，允许 1–8 |

“恢复全部默认值”也会先暂存，点击“保存”才生效。更改并发上限不会强行中断已经运行的请求。升级会保留之前显式保存的设置；要采用新默认策略，请将准备时机设为 **100%**、预热设为 **关闭**，或恢复默认后保存。

## 适合谁？有什么边界？

适合长时间编码、频繁调用工具、经常遇到上下文压缩停顿的任务。短对话或模型服务已满载时，收益可能很小。

- **减少等待，不承诺零等待。** 若摘要尚未完成，达到安全等待线时仍需等它；停止回合可以立即打断等待。新摘要与新增尾部仍需要 prefill，默认由应用后的真实请求完成，因此首 token 仍可能有等待。
- **预热不是免费加速。** 输出通常只有 1 token，但长输入仍可能需要大量 prefill，并与主请求争抢资源。缓存收益取决于前缀一致性及服务端的复用与驱逐策略；`maxConcurrent` 只限制后台摘要数量，不代表后台任务与主请求不会重叠。无效时可关闭预热。
- **后台摘要可能白做。** 回合结束、选中内容发生变化，或摘要没有缩小内容时，准备结果会被丢弃。
- **前缀相同不保证缓存命中。** Qwen 混合模型还依赖服务端保留相应的 recurrent checkpoint。插件消除竞争裁剪，不能保证摘要截断点一定有可恢复状态；这部分需要部署侧另行验证。
- **尚无真实端点的性能基准。** 图示说明流程，不代表固定提速比例。

<details>
<summary>实现细节与高级配置</summary>

- 提前生成阶段不写入会话日志；提交时追加 `compaction/start`、`compaction/summary`、替换消息和 `compaction/end`。
- 输入上限 `I = contextWindow − reservedCompletion`，等待线 `W = floor(I − safetyMarginTokens)`，后台准备基线 `T = floor(min(contextWindow × thresholdRatio, I − ceil(headroomTokens / 2), W))`；实际准备线为 `floor(T × eagerRatio)`。例如窗口 262,144、输出预留 32,768、headroom 65,536、安全余量 4,096 时，输入上限 **229,376**、准备线 **196,608**、等待线 **225,280**。196K 是准备时机，不是输入容量上限。
- 输出预留取请求/适配器声明与 `outputReserveTokens` 下限中的较大值；缺少声明且下限为 0 时沿用原生压缩，不把未知预留当成零来扩大后台推进空间。该设置不会改变模型实际输出参数。不同模型可使用不同的实际输出上限，全局下限对更小模型可能过于保守。
- 宿主负责设置、诊断和共享并发；压缩引擎在 standard/ptc/cordis 原有隔离组内替换原生后端。自动步骤、手动命令和 overflow 使用同一服务。保留 preset 策略、工具裁剪器和其他插件，不复制 preset 清单，不修改 DSH 发布文件。minimal、禁用自动压缩和第三方后端保持原样。
- 正常后台路径不裁剪旧工具结果。失效选区会立即取消准备；故障、预算紧张或 overflow 才先取消冲突工作，再走原生裁剪、重测和同步摘要。原生裁剪是有损恢复手段，可能破坏前缀缓存；完整原文仍在会话日志。
- 压缩历史沿用 DSH 宿主的已认证访问边界，不提供额外的多用户归属隔离；`observeSession` 用于解析和验证会话，不是用户授权检查。摘录会额外保存在本机诊断文件中，隐藏标签页不删除它们。清理敏感会话时也需清理对应诊断文件，参见上方的诊断目录说明。
- 压缩历史的诊断数据包含输入上限、输出预留、准备线与等待线；未接管或输出预算未知时页面会提示。
- 余量用于延续任务，不保证摘要一定能及时完成。失败、无可压缩选区及溢出仍遵循原生处理；token 估算与服务端实际 token 数可能不同。并发名额不足时只在安全预算内推迟准备，到等待线仍走同步回退。
- 正常回合结束不会丢弃已有准备：运行中的摘要可继续完成，准备好的结果留待下一轮安全步骤重新校验后应用；不会在空闲时改写会话。用户取消、异常结束、选区被替换、会话销毁和插件卸载仍会取消准备。每个压缩引擎最多保留 24 个空闲会话的准备，超出时释放最早保留的结果；未应用结果不跨进程重启恢复。
- 摘要异步完成时不修改正在使用的上下文；只在下一安全步骤提交。即使开启预热也不等它完成，提交时取消未完成的预热。
- 提交后重新检查总压力。预生成摘要的提交计作第一次尝试，剩余压缩次数受原版 `compactionRetries` 限制。
- 预热会发送尚未持久化的检查点文本。若要求所有发给模型的文本都已先落日志，请关闭预热。
- 压力估算对中日韩文本可能偏低。若准备启动太晚，可在设置页调低“后台准备时机”。
- 原版后端的高级字段仍可在 `faster-compress` 行配置，例如 `thresholdRatio`、`headroomTokens`、`retainTokens`、`modelPolicies`。普通使用不需要改动它们。
- 新增字段对应 `eagerRatio`（大于 0、不超过 1）、`warmup`、`maxConcurrent`、`warmupMaxTokens`、`traceTab`、`outputReserveTokens`、`safetyMarginTokens`。设置页里的 100% 对应 `eagerRatio: 1`。

</details>

## 开发与验证

```sh
npm install
npm run build
npm test
npm run check
npm pack
```

发布包已包含浏览器设置页和中英文 SVG，用户安装时不需要构建。服务端直接运行 JavaScript；浏览器端复用 DSH 的原生表单、保存与恢复默认交互。

回归测试覆盖阈值与区间选择、摘要取消、预算重试、预热开关与失败回退、真实 DSH Session 提交和回放，以及设置的校验与实时读取。模型 I/O 使用测试桩，未替代真实端点的性能验证。

压缩历史另有持久化恢复、会话隔离、记录上限、异常存储、应用状态投影及 RPC 生命周期回归。浏览器联调方法见 [测试说明](https://github.com/GallenShao/dsh-faster-compress/blob/main/tests/README.md)，使用隔离 `DSH_HOME`，不改日常配置。
